# CLAUDE CODE DIRECTIVE — Fully-Local Terminal Coding Agent on the RTX 5090 Windows Machine

> **Revision 2, 2026-08-15.** Revision 1 was written before any of this had been built. It has since been **executed end to end on a different box** — an 8 GB RTX 4060 laptop running Ubuntu, with Qwen3.5-4B — and roughly a dozen of its assumptions turned out to be wrong. This revision corrects them.
>

You are Claude Code on a Windows 11 machine with an NVIDIA RTX 5090 (32 GB, Blackwell, **SM120**). Perform a complete, idempotent installation of a local coding-agent stack, then hand the owner three commands: `agent up`, `agent code`, `agent down`. The owner is moderately technical and will never edit a config or debug a container. Everything must work from PowerShell / Windows Terminal.

Work phase by phase. Verify before proceeding. Log everything to `C:\agent-stack\INSTALL_LOG.md`.

## What the dry run established (do not re-derive these)

**Confirmed sound — the architecture transfers unchanged:**

- Bare-metal llama.cpp + GGUF is the right backend. Hybrid KV math works out as revision 1 predicted: **only full-attention layers carry KV**, and the GatedDeltaNet recurrent state is **flat in context length** (50 MiB at 4k, 50 MiB at 131k). Predicted vs observed VRAM agreed within ~20 MiB.
- MTP speculative decoding is real and worth it: **1.45× decode** (80 vs 55.5 tok/s) for +924 MiB, 0.71 draft acceptance.
- Fused Gated Delta Net kernels exist and engage.
- SearXNG + an MCP tool surface works. Tool calling is reliable: **10/10 well-formed, 26–45 tokens per call.**
- `agent up` / `agent down` as the entire user interface is the correct product decision.

**Corrected — revision 1 was wrong about these:**

| Revision 1 said | Reality |
|---|---|
| `--np 1` | **Invalid flag.** It is `-np` / `--parallel`. Hard startup failure. |
| `--jinja` needed for tool calling | **Default-enabled.** Harmless, but not the fix if tool calls break. |
| (nothing about thinking mode) | **The single biggest blocker.** See below. |
| `sched_reserve: fused Gated Delta Net ... enabled` in startup logs | Renamed to `resolve_fused_ops:` **and hidden at default verbosity.** Needs `-lv 5`. |
| Build the scraper with `spider` + `article_scraper` | Works, but `reqwest` + `dom_smoothie` + `htmd` measured **13–37× faster and 11× lighter** than a headless browser. Reference build ships it. |
| Groq round-robin across keys multiplies the free tier | **False.** Limits are **account-scoped**. More keys on one account add nothing; a second *provider* does. |
| SearXNG is the search layer | **Single point of failure.** All three engines CAPTCHA'd mid-session and search returned nothing. Add keyless structured APIs + RRF fusion. |
| Skip RAG/vector DB unless trivial | **Correct, and now for a measured reason:** agentic `ripgrep` beats vector RAG by **20–24% at 3B–7B**. Don't build a code index at all. |

## PHASE 1 — llama.cpp (bare-metal Windows CUDA)

Prefer a prebuilt Windows CUDA release with SM120 support. Otherwise build:

```
git clone https://github.com/ggml-org/llama.cpp.git
cmake -B build -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=120 -DLLAMA_CURL=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j
```

**Blackwell needs a CUDA 12.8+ toolkit.** Older toolkits do not know SM120 and will fail to compile or silently fall back to a slower path. Confirm compute capability from the runtime (`llama-server.exe --version` prints it), not from a table.

**Verify:** `--version` reports the CUDA backend; `--help | findstr spec-type` lists `draft-mtp`.

## PHASE 2 — Model download

Compute the KV budget from `config.json` **before** downloading 15–20 GB:

```
KV bytes/token = full_attention_layers × (n_embd_k_gqa + n_embd_v_gqa) × 1.0625   [q8_0]
```

Take `n_embd_k_gqa` / `n_embd_v_gqa` from `print_info` once loaded, or derive from `num_key_value_heads × head_dim`. **Count only `full_attention` entries in `layer_types`.** Do not assume the 4B's numbers — it was 8 of 32 layers and 17 KiB/token; the 27B will differ in every term.

Then: `usable − weights − recurrent − compute buffer − MTP context − CUDA context − 2 GB desktop margin = KV budget`.

**Two terms you must measure rather than assume:** the weight file size, and the **MTP draft context** — it was 682 MiB against 3,141 MiB of weights on the 4B (~22%). If that ratio holds, budget **2–4 GB** at 27B. Read it from the log: `srv load_model: [spec] estimated memory usage of MTP context is XXXX MiB`.

**Verify:** short-context smoke test at `-c 4096` before committing to full context. Seconds to fail instead of minutes.

## PHASE 3 — Server config

```
llama-server.exe
  --model C:\agent-stack\models\<file>.gguf
  --alias qwen3.8-27b
  --n-gpu-layers 99
  -c <computed>
  -fa on
  --cache-type-k q8_0 --cache-type-v q8_0
  --spec-type draft-mtp
  --parallel 1
  --reasoning off
  --host 127.0.0.1 --port <verified-free>
  --jinja
```

### `--reasoning off` — read this before anything else goes wrong

**This was the single biggest blocker in the dry run.** With thinking enabled, a trivial coding task ("add a two-line function and a test") generated **12,936 tokens in one completion** and was killed by the operator.

A controlled 8-run follow-up ([`experiments/reasoning-budget/`](experiments/reasoning-budget/README.md)) established the honest version:

| Config | Mean tokens | Mean time | Correct |
|---|---|---|---|
| thinking on, loose prompt, cap 8,192 | 6,458 | 80 s | 3/3 |
| thinking on, specific prompt, cap 32,768 | **32,702** | 381 s | 2/2 |
| **thinking off**, specific prompt | **395** | **12 s** | 3/3 |

**It is a cost failure, not a correctness failure — every run produced correct code.** But it costs **16–83×**.

Two things that do **not** help, both tested: a more specific prompt made it *worse*, and **a bigger output budget made it strictly worse** — one completion expands to fill whatever ceiling you set (32,669 and 32,736 tokens against a 32,768 cap). **Do not raise `limit.output` to "give it room to think."**

Test `--reasoning off` on the 27B immediately, and judge on **cost, not correctness**. Whether a 27B reasons more efficiently is genuinely unknown.

### Auto-fit — try it before hand-tuning

Recent llama.cpp fits parameters to free VRAM automatically, and an explicit `-ngl` **disables** it (`common_fit_params: ... n_gpu_layers already set by user to 99, abort`). On a 32 GB card with a 27B, **launch once without `-ngl` and `-c` and see what it picks** before overriding.

### Verifying GDN

```
llama-server.exe ... -lv 5 2>&1 | findstr /i "gated delta"
resolve_fused_ops: fused Gated Delta Net (autoregressive) enabled
resolve_fused_ops: fused Gated Delta Net (chunked) enabled
```

**Absence at default verbosity means nothing.** Raise the log level before concluding GDN is off.

### Prefix caching — protect it

`--cache-ram` (default 8192 MiB) gives host-memory prompt caching, and it is worth a great deal. Measured on the dry-run box, 21k-token prompt:

| | Prefill |
|---|---|
| cold | **11,651 ms** |
| shared prefix | **843 ms** (13.8×) |
| repeated | **238 ms** (49×) |

**This makes prompt-prefix stability an architectural constraint.** Anything that rewrites the front of the prompt — changing the system prompt, switching agents mid-session, injecting retrieved context at the top, or **changing the tool list** — forces a full reprocess. On the dry run, varying the tool list mid-session reprocessed up to 8,845 tokens per change.

Note also: `--cache-reuse` (mid-sequence KV shifting) **does not work with recurrent-state models**, which includes this family. Plain longest-common-prefix continuation does, and that is where the win comes from.

**Verify:** boots without OOM, `/v1/models` reports the **alias** (not the filename — without `--alias` the id is the GGUF filename and the OpenCode config breaks on every quant swap), `nvidia-smi` matches your prediction within ~50 MiB, and a ~25%-of-context prompt does not spike VRAM (it won't — the compute buffer is pre-reserved; a 31k prefill moved VRAM ~20 MiB).

## PHASE 4 — Search services (Docker Desktop)

Ports: SearXNG on a verified-free port; **`extractd`** (Phase 5) native, no container; crawl4ai optional as a browser fallback rung.

**SearXNG ships with JSON output disabled.** Add `json` under `search.formats` in `settings.yml`, set a non-default `server.secret_key`, restart. The reference `agent up` does this patch automatically — port it.

**Expect degraded engine availability as the normal case, not an exception.** SearXNG returns **HTTP 200 with an empty `results` array** when its upstream engines are throttled — it looks exactly like "no results found." Always read `unresponsive_engines`, and retry once on empty. Throughout the dry run Brave was rate-limited and Startpage CAPTCHA-suspended; eventually DuckDuckGo failed too and search returned nothing at all.

**Which is why SearXNG must not be the only source layer.** Port `mcp/sources.mjs` from the reference build: keyless adapters for **arXiv, Semantic Scholar, HN Algolia, Stack Exchange** (plus GitHub if a token exists), queried **concurrently** with SearXNG and fused by **Reciprocal Rank Fusion**. With all three SearXNG engines down, this returned six relevant papers for a query that had returned nothing an hour earlier.

## PHASE 5 — Local extraction service

**Do not make a headless browser the default.** Port `extractor/` from the reference build — a 7.8 MB Rust binary (`reqwest` + `dom_smoothie` + `htmd`) exposing `POST /extract` and `POST /extract_batch`.

Measured against headless Chromium on 8 Wikipedia articles:

| | extractd | crawl4ai |
|---|---|---|
| Wall clock, 8 URLs | **0.52 s** warm / 1.51 s cold | 19.43 s |
| Content | **876,656 chars** | 785,212 chars |
| Resident memory | **50 MiB** | 543 MiB |

Keep a browser rung as **fallback** for pages that genuinely need JS. The reference MCP server batches everything to `extractd` first and retries only the misses on the browser.

## PHASE 6 — OpenCode + MCP + optional remote lanes

**Local-only is the complete, default, zero-config product.** Remote providers are a bolt-on.

1. Install OpenCode; record version.
2. **Config schema is V2** (definitions are literally named `ConfigV2.*`). Copy `config/opencode.json` from the reference build and change `baseURL`, the model key, and `limit.context`. Field traps:
   - **`apiKey` is required** even though llama-server ignores it — the SDK won't construct a client without it.
   - **`reasoning` / `interleaved` must match the server.** With `--reasoning off`: `"reasoning": false` and **omit `interleaved`**. Mismatched, the agent appears to return empty responses.
   - Model key must equal `--alias`.
   - **Use an absolute path to `node`** in the MCP `command` array — a spawned subprocess may not inherit a PATH containing it.
3. MCP tools: port `mcp/search-server.mjs` (`web_search`, `web_fetch`, `deep_research`).
4. **Remote providers — optional, additive, silent on failure.** Port `mcp/lanes.mjs`. The design correction: limits are **account-scoped**, so real concurrency is the **sum of per-provider lanes** (Groq + Cerebras + local), not the number of credentials. Credentials within a lane spread that account's allowance and survive a bad one. The **local llama-server is the last lane** — it is why the pipeline degrades instead of failing. Verified: with every remote credential throttled, a summary was still produced locally.
5. **Tool count is not a constraint here.** Published work says ~8B models peak near 19 tools and fail at 46. **Measured on the dry-run model: 100% selection accuracy at 150 tools**, no degradation, flat generation cost — llama.cpp's function-calling grammar restricts the tool name structurally. Add tools on their own merits. What matters is that the tool list stays **stable within a session** (see prefix caching).
6. **Skip vector RAG entirely.** Agentic `ripgrep` beats it by 20–24% at this scale.

**Verify:** in a scratch repo with zero remote credentials, `agent code` writes a file, runs a shell command, and performs a web search — zero malformed tool calls, no errors about missing config. Then add one invalid credential and confirm the search still succeeds silently.

## PHASE 7 — Validation

Port `bin/toolcall-battery.py` and `projects/run-all.sh` from the reference build; both are ready to run.

- `/v1/models` responds with the alias.
- **Tool-call battery: 10/10**, zero malformed or looping.
- MTP acceptance from the logs. If poor, drop `--spec-draft-n-max` or remove `--spec-type` and log why.
- `agent bench` baseline — **this box's own number**. Never import the dry run's.
- Long-context: ~50k-token prompt, confirm no OOM and record TTFT.
- End-to-end: scratch repo, feature + test, green.
- `agent down` → VRAM idle.
- **`agent cache`** — prefix-cache hit rate. Anything reprocessing thousands of tokens mid-session means something is rewriting the prefix; hunt it.

**Known operational gotcha:** killing an OpenCode process leaves its SQLite WAL wedged, and the **next run hangs at `init` with no error**. Fix: `pragma wal_checkpoint(TRUNCATE)` on `opencode.db`. This bit the dry run repeatedly. Prefer letting runs finish; if you must kill one, checkpoint before the next.

Also: **never `pkill -f` on a pattern that appears in your own command line.** It kills the shell running the script. This happened three separate times during the dry run. Match process names exactly (`pgrep -x`).

## Global guardrails

- **Idempotency** everywhere; check-before-create.
- **Inventory before installing.** Never recreate or delete a container, build, or model another project may depend on — build alongside and note the ambiguity.
- Credentials live only in `.env`, never in a config that could be shared.
- If the bare-metal Windows CUDA build genuinely cannot be made to work, the sanctioned fallback is **WSL2 + llama.cpp** (not vLLM), keeping the same `agent` semantics via a `wsl -e` shim. Log the switch.
- **WSL2 caveats, if you go that route** (written from documentation, **not validated** — the dry run was native Linux): install the NVIDIA driver on **Windows only**, never inside the distro; install only the CUDA toolkit inside WSL2 from NVIDIA's WSL-Ubuntu repo; `libcuda.so.1` lives in `/usr/lib/wsl/lib`; keep the repo and models in the WSL filesystem, never under `/mnt/c`; raise WSL2 memory in `.wslconfig` if model loads are slow. Verify each of these rather than trusting them.

## Deferred — do not build in the first pass

The reference build carries a researched, tiered plan for augmentations beyond this core ([`docs/IMPLEMENTATION_PLAN.md`](docs/IMPLEMENTATION_PLAN.md), [`docs/RESEARCH_FINDINGS.md`](docs/RESEARCH_FINDINGS.md)): verification gates, an eval harness, a session journal, sleep-time consolidation, offline prompt optimization, continuous goal loops.

**None of it is required for a working stack, and the governing risk is maximalism** — a stack that does everything and is slow, fragile, or context-starved is worse than the agent that works today. Get Phases 0–8 green first. Revisit the plan afterwards, and only with measurements.
